## Change Control for This Governance Framework

*My own addition to the review's list — governing the governance artefacts themselves, not just the systems they govern.*

> Part of the Project 12 Agentic AI Governance portfolio — fictional example for educational purposes. See root README for the full disclaimer.

---

### The Gap This Closes

Every document in this project is itself an artefact that can go stale — a threshold that was right in Q2 and wrong by Q4, a control that turned out to generate constant false positives, a regulatory reference (like the EU AI Act's Digital Omnibus deadlines) that changes after publication. A governance framework that governs everything except its own drift is incomplete. This is a short, deliberately small document, because the point isn't to add more process — it's to make explicit the one thing that's usually implicit and therefore skipped.

### Requirements

| Requirement | Detail |
|---|---|
| Version and date on every document | Each artefact in this project states when it was last substantively reviewed, not just when it was created |
| Change trigger | Any regulatory change relevant to the Compliance Crosswalk, any Charter Section 6 escalation, or any Assurance Framework "Improve" finding triggers a review of the specific document(s) affected — not an assumption that the whole project needs re-reading |
| Approval for substantive changes | Changes to risk thresholds, decision-rights assignment, or control definitions go through the AI Governance Committee (Direct decision rights), same as a new system would |
| Superseded-version retention | Prior versions are kept, not overwritten — so an incident investigation can establish what the policy actually said at the time of the incident, mirroring the same requirement this project already places on prompt and model versions |

### Applied to This Project

The Risk Classification Addendum is the clearest live example: it was written to take a defensible position on an unresolved regulatory debate. If that debate resolves in either direction, this change-control requirement is what ensures the Addendum gets formally revised rather than silently becoming outdated while everything downstream (the Control Library, the Compliance Crosswalk) still cites it as current.

### Why This Belongs Here Rather Than as a Generic Statement

It would be easy to leave version control as an unstated assumption. Naming it as its own artefact is a small thing, but it's the difference between a portfolio that looks complete on the day it's published and one that demonstrates the author has thought about what "complete" means six months later, after the regulatory ground has shifted again.
